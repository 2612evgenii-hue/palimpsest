# Память и длинные документы v3

## Принцип

Контекст — рабочее окно, а не источник истины. Истина хранится в файлах,
привязанных к текущим SHA-256.

Слои:

| Слой | Файл | Назначение |
|---|---|---|
| состояние | `STATE.json` | политика, доказательства, гейты, события |
| горячий индекс | `MEMORY.md` | короткое текущее резюме |
| карта | `SEGMENTS.json` | полное неперекрывающееся покрытие длинного текста |
| тёплые артефакты | `master-brief.json`, `ductus.json`, ledgers | фазовые решения |
| холодный слой | `notes/`, `reports/`, `evidence/` | детали по запросу |
| мост | `HANDOFF.md` | точка возврата после паузы или compaction |

## Что значит «прочитать весь длинный текст»

Не загружать его одним сообщением и не читать выборочно. Нужно:

1. построить точную карту;
2. прочитать все сегменты по порядку через `pack`;
3. зафиксировать функцию каждого сегмента и зависимости между ними;
4. только затем принять `master_brief`.

Так полное чтение становится проверяемым процессом, а не заявлением.

## Точная карта

```bash
python3 scripts/segment.py map workspace/working.md \
  --out workspace/SEGMENTS.json
python3 scripts/segment.py --map workspace/SEGMENTS.json status --json
```

Инварианты карты:

- первый диапазон начинается с 0;
- каждый следующий начинается ровно там, где закончился предыдущий;
- последний заканчивается на длине файла;
- сумма диапазонов равна длине файла;
- SHA каждого сегмента соответствует текущему диапазону;
- `file_sha256` соответствует всему файлу.

После любой правки:

```bash
python3 scripts/segment.py --map workspace/SEGMENTS.json sync \
  --file workspace/working.md
python3 scripts/segment.py --map workspace/SEGMENTS.json status --json
```

`sync` сохраняет ID точных и достаточно похожих сегментов, помечает изменённые,
назначает новые ID добавленному содержимому и перечисляет исчезнувшие старые ID.
Результаты детекторов живут в `STATE.json`, поэтому старый SHA автоматически
делает их неактуальными.

## Рабочий цикл

```text
next → pack ID → прочитать стыки → правка → sync → status → verify
```

Не меняй соседний сегмент, если он не входит в текущий пакет. Если изменение
переходит границу, открой оба сегмента и запиши общий move.

## Detector coverage

`full` — каждый текущий сегмент имеет результаты каждого выбранного сервиса.

При F1 `score_mandatory` разрешён только `full`: каждый текущий сегмент имеет
результат каждого обязательного сервиса. Worst segment определяет pass сервиса.

`risk_sampled` может использоваться только вне score-mandatory для отдельной
диагностики. Тогда он включает:

- новые и изменённые сегменты;
- сегменты с risk-тегами;
- явно названные `sample_ids`;
- детерминированную выборку из остального документа.

Выборка не доказывает состояние всего текста и никогда не завершает F1.

## Compaction

Перед паузой:

```bash
python3 scripts/memory.py --workspace workspace refresh
python3 scripts/memory.py --workspace workspace handoff \
  --next "проверить S014 после правки причинности"
```

После compaction первое действие:

```bash
python3 scripts/memory.py --workspace workspace resume
```

Затем открывай только названный артефакт или сегмент. Нельзя продолжать с фразы
«насколько я помню».

## Поиск

```bash
python3 scripts/memory.py --workspace workspace recall "точная фраза"
python3 scripts/memory.py --workspace workspace recall "pattern" --regex
```

По умолчанию запрос литеральный. Регулярное выражение включается явно, поэтому
пунктуация пользователя не меняет смысл поиска и не вызывает ошибку компиляции.

## Конкурентные записи

`STATE.json`, карта, заметки, memory и handoff обновляются через advisory lock и
атомарную замену. Это защищает читателей от частично записанных файлов. Оно не
разрешает двум редакторам независимо менять один и тот же смысловой участок:
такую работу всё равно нужно координировать на уровне сегментов.
