# Проверка Palimpsest v3.2

## Что считается приёмкой

Не количество тестов, а способность воспроизвести реальные провалы:

1. смысловая инверсия;
2. устаревшее evidence после правки;
3. waiver, расширившийся на другой сервис/сегмент/SHA;
4. один сервис, ошибочно закрывший всё detector coverage;
5. новый абзац вне карты;
6. дубль брендов, ошибочно посчитанный независимым;
7. ложный «manual green» или force close;
8. плагиатная близость без локального отчёта;
9. несуществующий/изменённый evidence-файл;
10. memory recall, сломанный пунктуацией запроса;
11. подделка guest access или language capability;
12. bare detector score без challenge/raw capture;
13. may→must, because→despite, kg→lb, swap акторов и удаление тезиса;
14. режим без внешнего reference, ошибочно отключивший style gate;
15. повышение/понижение уровня английского;
16. synthetic long-form tail/segment loss и разрастание hot memory;
17. выдуманный `authorized_change` с чужим source-unit excerpt;
18. русский source, ошибочно объявленный `--language en`;
19. локально выдуманное согласие для yellow close;
20. synonym-only plateau с ложными mechanism labels;
21. мягкий one-band English-level drift.

## Автоматический набор

```bash
cd .agents/skills/palimpsest
python3 -m py_compile scripts/*.py evals/*.py
python3 evals/v3_acceptance.py
python3 evals/test_regressions.py
python3 evals/test_stress.py
python3 evals/selftest.py
python3 /path/to/skill-creator/scripts/quick_validate.py .
```

Три слоя обязательны:

- `v3_acceptance.py` — adversarial обходы и сквозные state contracts;
- `test_regressions.py` — широкий набор pattern/style/minimality/docs/memory/
  segment/overlap/English-level регрессий;
- `test_stress.py` — гетерогенный синтетический 15k+ word longform,
  lossless sync/pack/sample, полный source-unit tail и bounded disk memory.

Stress-слой проверяет инфраструктуру на синтетическом longform. Он не является
book-scale редакторской апробацией, не доказывает качество смысла на рукописи и
не должен так называться в отчёте.

`selftest.py` загружает все три слоя. Его итоговое число тестов нужно сообщать
вместе со слоями, а не продавать как самостоятельное доказательство качества.

## Реальная апробация

Для каждого релиза нужен как минимум один сквозной проект:

- английский текст целевого жанра;
- внешний style reference и отдельный `source_as_reference` сценарий;
- английский текст с фиксированным learner level;
- baseline и финальный diff;
- полный semantic review;
- прямой ZeroGPT + Copyleaks на одном SHA;
- longform-сценарий с добавленным абзацем и `sync`;
- F4-сценарий с намеренно близким источнику фрагментом;
- закрытие state без ручных подмен.

Для yellow gates автоматическая приёмка намеренно невозможна: локальный процесс
не аутентифицирует согласие пользователя. Проверяется переход только в
`READY_WITH_LIMITS` с non-zero return code.

Проверить не только happy path:

- сервис требует регистрацию;
- сервис возвращает противоречивый human false positive;
- результат исчезает или не появляется;
- текст превышает лимит;
- после финального замера меняется одно слово;
- capability review стареет или редактируется.

## Корпус детекторов

Минимальный release-корпус для выбора core:

- ≥12 AI-текстов минимум четырёх жанров;
- ≥12 human controls с доказуемым происхождением;
- одинаковые тексты и границы для всех сервисов;
- заранее фиксированный порог;
- сырые результаты, сбои и версии моделей;
- AI recall, human false-positive rate, separation и coverage;
- отдельный слой частично отредактированных/смешанных текстов.

Пилот 3+3 годится для выявления явного провала или дубля, но не для обещания
точности.

## Критерии выпуска

Релиз блокируется, если:

- `quick_validate` не проходит;
- любой Python-файл не компилируется;
- любой adversarial сценарий проходит «зелёным»;
- документация требует отсутствующую команду;
- default detector core требует регистрацию/оплату;
- registry и detector reference расходятся;
- сквозной проект нельзя повторить по сохранённым файлам;
- отчёт преувеличивает evidence.

## Честная формулировка

«Протестировано» должно включать:

- что именно проверено;
- на каком корпусе;
- дату и версии;
- какие результаты полные, а какие ограничены;
- что автоматизация доказать не может.

Слова «идеально», «гарантировано» и «выше всех конкурентов» не являются
критерием качества и не должны появляться в релизном отчёте без соответствующего
сравнительного исследования.
