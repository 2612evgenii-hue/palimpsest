# Верность v3.5: машинный экран и смысловая сверка

## Два разных доказательства

`fidelity_check.py` ловит только детерминированные риски:

- исчезнувшие или изменённые числа и их порядок;
- защищённые URL, цитаты, формулы, кодовые фрагменты;
- явные смены отрицания;
- смены единиц при сохранённом числе;
- сдвиги модальности (`may` → `must`, «может» → «должен»);
- явные подмены логической связи (`because` → `despite`);
- вероятный обмен ролями двух акторов;
- удаление claim-bearing предложения;
- известные RU/EN пары полярности: рост/снижение, подтверждает/опровергает,
  разрешает/запрещает и т. п.

Он не понимает тезис, скрытую причинность, прагматику, иронию, акцент или
жанровую функцию. Его `ok=true` означает «экран не нашёл перечисленных
аномалий», а не «смысл гарантирован».

Эти дополнительные правила консервативны и могут дать false positive. Поэтому
G7 требует ещё полный `semantic_review`, а не автоматическое принятие результата.

## Обязательная смысловая матрица

Сверяй оригинал и текущий текст по адресам:

| Ось | Вопрос |
|---|---|
| тезис | основной вывод тот же? |
| утверждения | ни одно обязательство не исчезло и не появилось? |
| полярность | поддержка не стала критикой; запрет — разрешением? |
| числа/единицы | значение, единица, диапазон и объект числа те же? |
| причинность | причина, условие и следствие не поменялись местами? |
| модальность | «может» не стало «должно» или «доказано»? |
| хронология | последовательность и временные рамки сохранены? |
| жанр | функция абзаца/раздела сохранена? |
| намерение | просьба, предупреждение, обещание, оговорка остались теми же? |

Шаблон создаёт immutable `source_units`: предложения для surgical и абзацы для
standard/longform. Для каждой единицы обязательно:

- сохранить неизменяемые `id`, source digest и excerpt;
- выбрать `preserved` или `authorized_change`;
- привести verbatim excerpt текущего текста, location и точные
  `start_char`/`end_char`;
- дать содержательное объяснение;
- для `authorized_change` приложить структурированную внешнюю authorization
  claim, связанную с этим `source_unit_id` и source SHA.

Случайная фраза длиной 20 символов больше не является достаточной
самоаттестацией: evidence должен существовать в текущем working text, а
preserved mapping — иметь лексическую связь с исходной единицей. Диапазоны
разных source units не могут повторно использоваться, пересекаться или идти
в обратном порядке.

Локальный процесс не способен доказать, что citation authorization действительно
написал пользователь: он может выдумать и цитату, и ID сообщения. Поэтому
`authorized_change` — объявленное внешнее исключение, а не доказательство:
валидный артефакт оставляет G7 **красным** и не может быть локально закрыт. Для
зелёного G7 изменение должно быть `preserved`. Если пользователь действительно
попросил изменить содержание, сначала внести подтверждённое изменение в новый
immutable source baseline и заново инициализировать проект; локальная цитата не
подменяет provenance.

## Reconciliation lexical coverage

Глубокая, но верная переформулировка может дать false positive
`CLAIM_DROPPED`/`CLAIM_ADDED`, потому что этот слой основан на lexical overlap.
G7 разрешает снять **только эти два** кода, когда:

- текущий `semantic_review` валиден и привязан к working SHA;
- каждая source unit имеет verdict `preserved`;
- dropped finding связан с точной immutable source unit;
- added excerpt целиком присутствует в exact edited mapping;
- offsets идут монотонно и не пересекаются.

Любой другой fidelity code остаётся красным. Ни semantic review, ни детекторы с
нулевым score не могут снять изменение числа, отрицания, модальности,
причинности, хронологии, цитаты, URL, формулы или protected literal.

## Защищённые фрагменты

По умолчанию защищены:

- URL;
- fenced/inline code;
- формулы и уравнения;
- явные цитаты;
- библиографические ссылки;
- числа и единицы;
- пользовательские protected fragments.

Если такой фрагмент должен измениться, это отдельное пользовательское или
фактологическое решение, а не стилистическая правка.

## Проверка

```bash
python3 scripts/fidelity_check.py \
  --original workspace/original.md \
  --edited workspace/working.md --json
```

Код возврата:

- `0`: детерминированный экран прошёл;
- `1`: найдены блокирующие расхождения;
- `2`: ошибка входа/аргументов.

После исправления обязательно повторить на полном текущем файле.

## Минимальность не равна верности

Одна замена может инвертировать смысл, а целый перестроенный абзац может
сохранить его. Поэтому:

- `minimality.py` ограничивает масштаб;
- `fidelity_check.py` ловит известные якоря;
- `semantic_review` отвечает за смысл;
- side-by-side чтение отвечает за остаточный риск.

Ни один слой не заменяет остальные.

## Красные примеры

Блокировать:

- `grew by 8%` → `fell by 8%`;
- `x = 1` → `x = 9`;
- `the study confirms` → `the study refutes`;
- `may improve` → `will improve`;
- `may publish` → `must publish`;
- `because the sensor failed` → `despite the sensor failure`;
- `10 kg` → `10 lb`;
- `the regulator warned the bank` → `the bank warned the regulator`;
- «после события» → «из-за события», если причинность не доказана;
- удаление оговорки, меняющей область применимости.

Даже если все детекторы после этого показывают 0%, текст неприемлем.
